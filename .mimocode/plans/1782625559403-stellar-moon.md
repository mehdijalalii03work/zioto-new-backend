
# Fix: Admin Login on Production Server

## Root Cause Analysis

صفحه لاگین بدون ارور ریلود می‌شه. این رفتار معمولاً به این معنیه که **CSRF token mismatch** رخ میده ولی Livewire اون رو ساکت catch می‌کنه و صفحه رو ریدایرکت می‌کنه بک به لاگین. دلیلش اینه که session بین درخواست GET (بارگذاری صفحه لاگین) و POST (ارسال فرم) حفظ نمی‌شه.

روی لوکال کار می‌کنه چون cookie domain/secure مشکلی نداره ولی روی سرور HTTPS مشکل‌ساز میشه.

## دلایل احتمالی (اولویت‌بندی شده)

### 1. SESSION_DOMAIN و SESSION_SECURE_COOKIE تنظیم نشده
فایل `.env` سرور:
- `SESSION_DOMAIN` روی `null` هست → cookie روی دقیقاً هاست scope میشه
- `SESSION_SECURE_COOKIE` تنظیم نشده → روی HTTPS ممکنه cookie با Secure flag set نشه

### 2. PreventRequestForgery دوبار اعمال میشه
`PreventRequestForgery` هم در `bootstrap/app.php:20` (global) و هم در `AdminPanelProvider.php:81` (panel middleware) وجود داره. این باعث چک CSRF دوباره میشه.

### 3. جدول sessions در دیتابیس سرور وجود نداره
Session driver روی `database` تنظیم شده. اگر migration اجرا نشده باشه، session ذخیره نمیشه.

## Plan

### Step 1: فایل `.env` سرور (دستی - نیاز به دسترسی سرور داره)

در فایل `.env` سرور این مقادیر رو تنظیم کنید:

```env
APP_URL=https://backend.sawiss.com
SESSION_DOMAIN=backend.sawiss.com
SESSION_SECURE_COOKIE=true
```

**نکته:** اگر اپ پشت reverse proxy (nginx) هست، در nginx هم مطمئن بشید این header ها تنظیم شده:
```
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

### Step 2: حذف PreventRequestForgery از panel middleware

فایل: `app/Providers/Filament/AdminPanelProvider.php:81`

چون `PreventRequestForgery` از طریق `bootstrap/app.php` به صورت global اعمال میشه، نیازی به تکرارش در panel middleware نیست. حذفش کنید:

```php
// قبل
->middleware([
    EncryptCookies::class,
    AddQueuedCookiesToResponse::class,
    StartSession::class,
    AuthenticateSession::class,
    ShareErrorsFromSession::class,
    PreventRequestForgery::class,        // ← حذف شود
    SubstituteBindings::class,
    DisableBladeIconComponents::class,
    DispatchServingFilamentEvent::class,
])
```

```php
// بعد
->middleware([
    EncryptCookies::class,
    AddQueuedCookiesToResponse::class,
    StartSession::class,
    AuthenticateSession::class,
    ShareErrorsFromSession::class,
    SubstituteBindings::class,
    DisableBladeIconComponents::class,
    DispatchServingFilamentEvent::class,
])
```

و import `PreventRequestForgery` (line 19) هم حذف بشه.

### Step 3: اجرای migration روی سرور (دستی - نیاز به دسترسی سرور)

```bash
php artisan migrate
```

مطمئن بشید جدول `sessions` وجود داره.

### Step 4: بررسی لاگ‌ها

```bash
php artisan pail
```

یا لاگ‌های سرور رو بررسی کنید تا مطمئن بشید خطایی ثبت میشه.

## فایل‌های تغییر یافته

- `app/Providers/Filament/AdminPanelProvider.php` - حذف `PreventRequestForgery` از panel middleware

## Verification

1. بعد از apply تغییرات، اپ رو deploy کنید
2. به `https://backend.sawiss.com/admin/login` برید
3. با اطلاعات صحیح لاگین کنید
4. بررسی کنید که به داشبورد ریدایرکت میشه
