# Plan: Fix shipping methods shown to users without an address

## Root Cause

`ShippingController::methods()` reads `city_id`/`province_id` from query params only. The route has no `auth.token` middleware.

**Frontend flow** (confirmed from `/Users/mehdi/Documents/ZiotoNewProjects/zioto-new-frontend/src/lib/api-client.ts:182`):
- User has address → frontend sends `city_id=X&province_id=Y` → backend filters correctly
- User has NO address → frontend sends no params → backend skips all filtering (line 20) → returns all 4 methods

### 2. Update `ShippingController::methods()` to auto-resolve user address
**File**: `app/Http/Controllers/Api/ShippingController.php:13-77`

When no `city_id`/`province_id` query params are provided, look up the user's default address (or first address):
- If user has an address → use its `city_id`/`province_id` for filtering
- If user has no address → only return methods where `is_pickup = true` (just `in_store_pickup`)

```php
public function methods(Request $request): JsonResponse
{
    $cityId = $request->input('city_id');
    $provinceId = $request->input('province_id');

    // Auto-resolve from user's address if params not provided
    if (! $cityId && ! $provinceId) {
        $user = $request->user();
        $address = $user?->defaultAddress ?? $user?->addresses()->first();
        if ($address) {
            $cityId = $address->city_id;
            $provinceId = $address->province_id;
        }
    }

    $methods = ShippingMethod::active()->with('rates')->get();

    // If no address found, only show pickup methods
    if (! $cityId && ! $provinceId) {
        $methods = $methods->filter(fn (ShippingMethod $m) => $m->is_pickup);
        return response()->json(['methods' => $methods->values()]);
    }

    // ... rest of existing filtering logic unchanged ...
}
```

### 3. Also handle `is_pickup` filtering in the address-based filter block
When user HAS an address, `in_store_pickup` should still be returned (it always works). The existing code already handles this because `in_store_pickup` has a flat rate with no province/city constraint.
