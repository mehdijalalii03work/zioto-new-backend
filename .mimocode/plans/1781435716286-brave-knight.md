## Part 2: Frontend Architecture Refactor

### Current Problem
`app.js` is a ~1100 line monolith with all rendering, state, routing, and business logic mixed together.

### Target Architecture
Split into focused modules:

```
public/js/landing/
├── app.js              # Bootstrap + router only
├── data.js             # Helper functions (formatPrice, etc.)
├── state.js            # Global state (currentPage, cart, userData, etc.)
├── router.js           # Route table, navigateTo, popstate handler
├── components/
│   ├── header.js       # renderHeader() + nav
│   ├── home.js         # renderHome(), renderProductCards()
│   ├── product.js      # renderProductDetail()
│   ├── cart.js         # renderCart()
│   ├── checkout.js     # renderCheckout()
│   ├── auth.js         # renderLogin(), OTP logic
│   ├── profile.js      # renderProfile(), tabs
│   └── about.js        # renderAbout()
```

### Implementation Steps
1. Create `state.js` — extract all state variables (currentPage, cart, userData, etc.)
2. Create `router.js` — extract routing logic (navigateTo, route table, popstate)
3. Create component files — extract each page's render function into its own file
4. Update `app.js` — bootstrap only (DOMContentLoaded, import order)
5. Update `data.js` — keep only utility functions (formatPrice, toPersianNum, etc.)
6. Update `index.blade.php` — add script tags in correct order

### Key Principles
- Each component file exports its render function(s)
- State is shared via a global `STATE` object in `state.js`
- Components read/write state via the shared object
- No build step needed — plain `<script>` tags in order
